# Acceptance checklist: Plans (v3)

Rewritten for v3 after the owner's feedback on the phase 1 build (verbatim in
`design/plans-deepdive/v3/README.md`). Nothing goes to the owner until an
independent auditor ticks every line against a frame, a measured fact or a test.
Frames: `design/plans-deepdive/v3/frames/` (`NN` = `NN-*.png`, 390x844 @1x; `@3x`
full screens and crops beside them; `-panel.png` = the whole panel, unscrolled).
Per-frame truths: `v3/truths.md` (generated by `harness/check.js`). Gestures:
`harness/griptest.js`. Numbers: `harness/measure.js` → `v3/measure.json`.

Superseded: v2's Edit mode, DONE, "Edit stops", hidden chips and hidden ⇅ (all
v2 lines about them are void; v2 stays in `v2/` as history).

## A. Filter panel parity (owner: "a filter panel that supports all the chips and location menu on both views")

- [ ] A1 The real app's panel controls, complete (checked against `index.html`: every `<button>`, `<input>`, `<select>`): the Places|Plans switch (`#listSwitch`); the city chips `#cityFilters` = LA, Reykjavík, Copenhagen, Malmö, Stockholm, ALL CITIES (single-select, runtime-extensible from `cities`); the rope divider; the category chips `#filters` = Restaurant, Cafe, Bar, Attraction, Nature, Shopping, Area, Hotel, Other, District, Street (multi-select; on = category rule, off = dashed). There is no other filter or location control in the panel.
- [ ] A2 Outside the panel, the location-related controls are: header ⇅ sort (incl. Nearest), header locate (`#centerMeBtn`), map zoom ±, and the add form's city select + place search. All exist unchanged in both views. The owner confirmed "location menu" = the city chips; the parity list is the city chips + the category chips (+ the sort menu, B7).
- [ ] A3 Both panels are identical: the switch (176px) and the plan picker share one 61px row, then the same city and category chips (frames 01+ and 02+; check.js asserts 6 cities + 11 categories in both). *(r2)* The Plans panel is **exactly** the height of the Places panel (0px difference, measured; was +46px). The picker's list is a slip over the chips, so opening it changes no layout (17).
- [ ] A4 One filter state for both views: switching views never changes the city, the chips or the sort (29+, griptest F2).
- [ ] A5 Picking a city or toggling a chip never changes the view (05, 07, 08, 09, 10, 11; griptest F1).
- [ ] A6 The switch changes only what the list shows (and so what the map draws); it never changes filters, sort or whether the panel is open.
- [x] ~~A7 The panel scroll is disclosed: at 390x844 the panel (max 40vh = 337px) scrolls 32px in both views, as Places did in phase 1.~~ *(superseded: L8, the panel no longer scrolls)*

## B. What the Plans list shows

- [ ] B2 Stops always show, whatever the filters: the chips choose what you can add, they never hide your plan (09: Cafe off, café stops 1 and 3 remain; 07: Malmö on, the Copenhagen stops remain). - [ ] B4 Adding from a filtered list: a near-still tap on + appends the place as the last stop; it moves above the rule with its number; the map gets its numbered pin; the slip says "Added <name> as stop n · Undo" (06; griptest P1–P3).

- [ ] B8 Which plan you are building is always visible: the header title is exactly the plan's name; the panel's picker shows it (and ✓ + count in its slip); the add slip names the place and its stop number ("Added Hart Bageri as stop 7"), the remove slip names the place ("Removed The Coffee Collective") (02, 03, 06, 13).
