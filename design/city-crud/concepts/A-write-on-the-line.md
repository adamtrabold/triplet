# A · Write on the line

**Every printed city name is writable where it stands.** The add tag's city line is itself a text
field: tap it and type; the menu below filters your cities and offers what you typed as a new
one. Cities are edited in the title menu's own edit mode (each name writable, a delete × each).
No new objects, no new surfaces.

Stills: `stills/5-A-write-on-the-line.png` (raws `A1`..`A3`).

## Draws on

- **The obvious-but-sharpened answer**: a combobox. Kept as the baseline so the owner can judge
  whether B's extra object is worth it.
- **"Faced with a choice, do both"** (random draw): the line is both the display and the input; no
  separate "new city" step.
- **iOS list edit mode** (Done in the menu's caption, delete per row).

## The moments

1. **Type the city.** Tap the city line: it becomes a 16px entry on a navy rule. Typing filters
   your cities; when none match: "None of your cities is called that", then New city: "+
   PHILADELPHIA" (what you typed, checked) and "+ WILMINGTON · where it is". Retype any time before
   ADD (J4).
2. **Edit cities.** Title menu → Edit (caption "EDIT CITIES · DONE"): each city's name underlined
   and writable, a × on each; "New city" at the foot.
3. **Delete.** The × opens the row: "Delete it? Its 1 place moves to [PHILADELPHIA ⌄]", CANCEL /
   DELETE.

## Rules

- A city's centre is never set by hand: it is the lookup of its name (a real town), else its first
  place. Renaming re-runs the lookup.
- Same guess, same hand-made / cleanup / delete rules as B.

## Weak spots

- J9 (change where a city is): only indirectly, through the name. A bucket called "Philly
  roadtrip" can't be corrected if its first place was a Delaware stop.
- No place to read a city (J7 is the list and menu only; no tally beyond the section's).
- Edit mode hides "All places" and changes the menu's job (a navigation menu that is sometimes a
  form); typing on a 12px caps line needs it to grow to 16px, so the line jumps when tapped
  (owner-taste: "Controls don't move or grow").
