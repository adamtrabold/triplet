# Star alignment — concept stage (legacy/safe track)

Problem: `.location-card.is-starred .row-main { padding-left: 26px }` only
indents the text column on starred rows, so a row's name/meta start at a
different x depending on starred state — "no clean grid." This track
explores fixes grounded in the app's own already-shipped precedent: a
**reserved column that is always present**, the same idea behind
`.row-badge` (the 28px category-glyph column, documented in `index.html`
as "the app's alignment spine") and the visited stamp's fixed action-cluster
slot — and in general list-app prior art (Apple Mail's flag column, Todoist's
priority dot, iOS Reminders' flag, Things 3's flag) where the flag's column
width never depends on whether a given row has a flag.

All three variants are built from real `index.html` tokens/markup
(`_shared.css`, `_sprite.html`, generated by `build.js`) and screenshotted
with headless Chromium at 390px width, 2x scale. Concept-stage only —
mockups are static HTML, no JS, not wired into `index.html`.

## Variant 1 — Nested grid, silent
`variant-1-nested-silent.html` / `.png`

Reserved 18px column lives **inside `.row-main`'s own grid**
(`grid-template-columns: 18px 1fr`) — the *exact* pattern the popup already
ships (`.popup-title-row { grid-template-columns: 18px auto }`), ported onto
the list row unchanged. The star renders only when starred; the column is
silent otherwise, mirroring `.row-stamp`'s shipped rule ("silence is the
unvisited state"). Outer 3-column ledger grid (glyph | content | action) is
untouched, so shape-card rows and the action cluster can't be affected.

**Rationale:** cheapest structural change that still uses a true reserved
column (not conditional padding), and reuses a pattern that's already
proven in this exact codebase.

## Variant 2 — Nested grid, always-visible
`variant-2-nested-always.html` / `.png`

Same reserved 18px column as Variant 1, but the slot **always** holds a
glyph — hollow (`--ink-2`) when unstarred, filled (`--ink`) when starred.
This is the Apple Mail flag-column / Todoist priority-dot pattern in its
more literal form: the affordance is discoverable from every row, not just
rows that already have it. It's also the option that matches what the
**popup already ships today** — `buildPopupHtml()` always renders
`#g-star` or `#g-star-open`, never nothing — so choosing this for the list
row makes list and popup use the identical rule, where Variant 1 would be a
deliberate new divergence between the two surfaces (not unprecedented: the
app already treats visited differently on the list, a stamp only when
true, vs. the popup, an always-visible "Mark Visited" button).

**Rationale:** most literal port of the classic flag-column affordance;
costs a small amount of visual noise on every unstarred row, the same
tradeoff the owner explicitly rejected once already for the visited dot
("unconditional... read as clutter, not signal" — CLAUDE.md).

## Variant 3 — Outer ledger column
`variant-3-outer-column.html` / `.png`

Extends the app's own documented alignment spine — *"28px glyph | 1fr
content | action"* — with a second fixed peer column
(`grid-template-columns: var(--col-glyph) 18px 1fr auto`), the same
technique `.row-badge` itself uses, rather than nesting inside
`.row-main`. Silent when unstarred, like Variant 1.

**Rationale:** the most literal reading of "give it its own fixed grid
column" (CLAUDE.md's exact phrase for the visited-dot lesson), applied at
the same level as the category glyph. But it touches the *shared* row
grid that shape-card rows and the action cluster also sit in — an
unstarred row's slot is absent from the DOM, so `.row-main` and
`.location-actions` need explicit `grid-column` pins or CSS auto-placement
will slide them left into the empty track. That's exactly the class of bug
CLAUDE.md's `grid-column: -1` shape-card history warns about — the main
added risk of this variant versus 1/2.

## UX self-check (concept-level only — not polish)

- **Tap-to-navigate:** unaffected in all three. The star glyph itself stays
  non-interactive/decorative in the list row (same as today); the row's
  existing click-to-navigate handler isn't touched by any of these layout
  changes.
- **Tap targets:** none of the three change any tap target size — this is
  a pure layout/reservation change, no new interactive elements in the
  list row.
- **Truncation at small widths:** all three cost real width from every
  row's name (18px glyph + 8px gap ≈ 26px, matching the existing 26px the
  owner is already paying on starred rows) — but now it's paid by *every*
  row, starred or not, not just starred ones. At 375–390px this trims
  another ~2 characters off the already-tight budget CLAUDE.md documents
  for the visited stamp (which found 17% of current names exceed the
  budget once stamped). Not a blocker, but worth measuring against real
  place names in the perfection stage, same as the stamp was.
- **Variant 3's specific risk:** covered above (grid auto-placement
  fragility without explicit `grid-column` pins on the neighboring cells).
  Concept-level blocker if shipped without those pins; not a blocker with
  them, but adds a maintenance trap Variants 1/2 don't have.
- **A11y:** no change from today in any variant — the star stays decorative
  (`aria-hidden`) with `.sr-only` as the one accessible source, per the
  existing rule for both star and visited state.

## Top pick

**Variant 1 (nested grid, silent).** It fixes the alignment bug with the
least new surface area (touches only `.row-main`'s internal layout, not the
shared row grid), reuses a pattern the codebase has *already* shipped twice
over (the popup's own `18px auto` grid, and the stamp's "silence by
default" rule), and keeps the list visually quiet for the common case
(most rows unstarred) — consistent with the owner's own prior call on the
visited dot. Variant 2 is the close second if the owner would rather the
star be a discoverable, always-visible column like Mail/Todoist/Reminders
(and it has the advantage of matching the popup's current behavior exactly,
where Variant 1 introduces a small list/popup divergence) — worth a direct
either/or check with the owner before building it for real. Variant 3 is
included to show the more literal reading of the badge-column precedent,
but its outer-grid fragility makes it the least attractive of the three
unless there's a reason to prefer matching `.row-badge` structurally over
matching the popup's own proven pattern.
